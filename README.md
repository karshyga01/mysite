# Tabigi Tas — сайт

Памятники, надгробия и мемориальные комплексы из камня. Алматы, свой карьер
и цех в Кордае. Рабочий домен — **https://www.tabigitas.kz**

Статический сайт: ни базы данных, ни движка. Страницы собираются из исходников
одним скриптом на Node.js, зависимостей нет.

---

## Быстрый старт

```bash
npm run build     # собрать сайт в dist/
npm start         # собрать и открыть на http://localhost:8901/
```

> Открывать файлы двойным щелчком (`file://`) **нельзя**: все адреса картинок
> и стилей начинаются со `/`, без сервера браузер их не найдёт и покажет
> страницу без оформления. Это не поломка сайта.

## Как устроена страница

Каждый файл в `src/pages/` начинается блоком данных, дальше идёт содержимое:

```html
<!--meta
{
  "url": "/musulmanskie-pamyatniki/",
  "title": "Заголовок в поиске, 50–60 символов",
  "description": "Описание в поиске, 120–165 символов",
  "image": "/images/файл.jpg",
  "imageAlt": "что изображено",
  "crumbs": [["Мусульманские памятники", null]],
  "schema": { }
}
-->
<section class="page-head">…</section>
{{> cta}}
```

- `url` определяет, куда ляжет файл: `/granit/alatagyn/` → `granit/alatagyn/index.html`
- `crumbs` — хлебные крошки. **`null` может стоять только у последнего элемента**,
  иначе в вёрстке появится ссылка `href="null"`
- `schema` — разметка для Google. Организация уже описана в `tools/build.js`,
  ссылайтесь на неё через `{"@id": "https://www.tabigitas.kz/#org"}`
- `{{> имя}}` вставляет блок из `src/partials/имя.html`
- `"noindex": true` закрывает страницу от поисковика (так сделана 404)
- `"lang": "kk"` + `"altLang": "/русский-адрес/"` — для казахских страниц,
  сборщик сам проставит `hreflang`

Сборщик добавляет сам: `<head>` со всеми мета-тегами, канонический адрес,
Open Graph, разметку организации и хлебных крошек, шапку, подвал и скрипты.

## Добавить фотографии

```bash
# 1. положить мастер-файл в images/ — имя латиницей и по делу
#    pamyatnik-kazahskiy-ornament-polumesyats-granit.jpg, а не IMG_2841.jpg
npm run images      # сделает облегчённые версии (нужен imagemagick)
npm run build
```

**Имя файла и `alt`** — это то, по чему картинку находят в Google Картинках.
В `alt` пишите русскую фразу так, как её ищет человек: «гранитный памятник
с казахским орнаментом».

## Чего нельзя делать

- **Не править файлы в `dist/`** — они стираются при каждой сборке.
- **Не использовать голый селектор `nav {}`** в CSS: на странице три таких блока
  (шапка, хлебные крошки, меню подвала). Шапка адресуется как `.site-header`.
- **Не убирать `height: auto` у `img`** в начале `styles.css`. Атрибуты
  `width`/`height` у картинки — это настоящее CSS-правило; без сброса высоты
  любой `aspect-ratio` игнорируется и картинка растягивается на свои пиксели.
- **Не ставить голые якоря** (`href="#pricing"`) — только от корня: `href="/#pricing"`.
- **Не удалять якоря `#pricing`, `#monuments`, `#contact`** на главной: по ссылкам
  из старой переписки в WhatsApp люди приходят до сих пор.
- **Не удалять `static/google3b6aed1b31b5e38f.html`** — это подтверждение прав
  в Google Search Console. Удалить = потерять историю поисковой статистики.
- **Замена фото = новое имя файла.** На `/images/` стоит кэш на год.
- **Не увеличивать картинки.** Мастер-файлы 900–1700 px по длинной стороне,
  запаса качества нет.

| Казахская версия и `hreflang` | страницы `/kz/…` + `altLang` в `meta` |
| Переадресация со старых адресов (301) | `redirects` в `vercel.json` |
| Кэш и заголовки безопасности | `headers` в `vercel.json` |
| Яндекс.Метрика, счётчик `111027451` | `static/app.js` |

### Цели в Яндекс.Метрике

Их нужно один раз создать в интерфейсе Метрики (тип «JavaScript-событие»),
идентификаторы уже отправляются из `app.js`:

| Идентификатор | Когда срабатывает |
|---|---|
| `wa_click` | клик по кнопке WhatsApp (в параметрах — какая именно) |
| `phone_click` | клик по номеру телефона |
| `email_click` | клик по адресу почты |
| `quiz_start` | человек начал отвечать в подборщике |
| `quiz_done` | подборщик дошёл до результата |
| `form_start` | начал заполнять форму заявки |
| `form_submit` | отправил форму |
| `wa_open_blocked` | WhatsApp не открылся, показан запасной блок |

## Публикация

Сайт статический, ему подойдёт любой хостинг статики. Собрать и отдать
содержимое `dist/`:

```bash
npm run build
```

`vercel.json` в корне описывает команду сборки, кэш, заголовки безопасности
и **16 редиректов со старых адресов** (`/granitnaya-plitka/`, `/bruschatka/`,
`/pamyatniki/ceny/` и других). При переезде на другой хостинг эти редиректы
нужно перенести — иначе накопленный поисковый вес старых страниц пропадёт.

После публикации:

1. В Google Search Console отправить `sitemap.xml` и `sitemap-images.xml`.
2. Проверить, что старые адреса отдают 301.
3. В Метрике создать цели из таблицы выше.

  `/mramor/` и `/prodazha-kamnya/` держатся на тексте и таблицах. Существующие
  фото намеренно не подписаны как эти камни — выдавать одно за другое нельзя.
- Фото процесса: карьер, распиловка, работа гравировщика, шоурум.
- Откуда привозной камень — если назовёте страну, страницы усилятся в поиске.
- Проверить казахские страницы (`/kz/…`) — текст писался автоматически.
- Отзывы клиентов: появятся настоящие — выведем блоком и разметим для Google.
